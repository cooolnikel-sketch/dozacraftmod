# WebcamBubbles — сайт для GitHub Pages

Статический адаптивный сайт-визитка на HTML/CSS/JS. Никакой сборки, npm или сервера не требуется.

## 1. Перед публикацией — обязательно настрой ссылки

Открой `config.js` и замени:

```js
repoUrl: "https://github.com/YOUR-USERNAME/WebcamBubbles",
releasesUrl: "https://github.com/YOUR-USERNAME/WebcamBubbles/releases/latest",
version: "1.2.4",
minecraft: "26.3"
```

на URL своего GitHub-репозитория и актуальную версию мода. Все кнопки скачивания и GitHub на сайте используют эти значения.

## 2. Как публиковать новые JAR

GitHub Pages — статический хостинг: форма на таком сайте не может записывать загруженные файлы обратно в репозиторий. Поэтому рабочая схема без сервера такая:

1. Создай GitHub-репозиторий, например `WebcamBubbles`.
2. Загрузи в него `index.html`, `styles.css`, `script.js`, `config.js`, папку `assets/` и этот README. Можно также распаковать файлы сайта прямо в корень репозитория.
3. Собери мод и получи JAR из `build/libs/`.
4. На GitHub открой **Releases → Draft a new release**.
5. Создай тег версии, например `v1.2.4`, добавь заметки релиза и прикрепи именно файл `webcambubbles-1.2.4.jar` (не исходный ZIP проекта).
6. Опубликуй релиз. Кнопки сайта откроют страницу последнего релиза, откуда посетитель сможет скачать JAR.
7. При следующей версии измени `version` в `config.js` и опубликуй изменения сайта.

## 3. Включить GitHub Pages

1. Открой репозиторий → **Settings → Pages**.
2. В разделе **Build and deployment** выбери **Deploy from a branch**.
3. Выбери ветку `main` и папку `/ (root)`, затем **Save**.
4. Подожди завершения публикации — GitHub покажет адрес сайта в этом же разделе.

Если сайт лежит в подпапке, для простоты всё равно рекомендуем положить файлы в корень Pages-репозитория. Тогда пути `styles.css`, `script.js` и `assets/favicon.svg` работают без дополнительной настройки.

## 4. Обновление сайта

Для новой версии:
- обнови номер в `config.js`;
- опубликуй новый GitHub Release с JAR;
- при необходимости обнови список возможностей, команды и FAQ в `index.html`.

## 5. Почему нет формы «загрузить JAR на сайт»?

Обычный GitHub Pages не поддерживает приём и сохранение файлов через HTML-форму — для этого нужен сервер/API с авторизацией. Нельзя безопасно помещать GitHub-токен в JavaScript на публичном сайте. GitHub Releases решает задачу хранения и раздачи JAR без собственного сервера и без раскрытия секретных ключей.

## Содержимое

- `index.html` — страницы и весь текст.
- `styles.css` — оформление, адаптация для телефонов, CSS-иллюстрация Minecraft-сцены.
- `script.js` — мобильное меню, поиск по командам, копирование команд и подстановка версии/ссылок.
- `config.js` — основные настройки сайта.
- `assets/favicon.svg` — иконка вкладки.

Сайт не использует аналитические скрипты или сторонние API. Google Fonts загружается с внешнего CDN; если нужен полностью автономный вариант, убери `@import` в `styles.css` — останутся системные шрифты.
