# DozaCraft — сайт на GitHub Pages

Статический сайт без сервера, без Cloudflare и без базы данных. Список версий
мода берётся из **GitHub Releases** репозитория `dozacraftmod` и один раз в
несколько часов (или сразу после публикации релиза) пересобирается в файл
`releases.json` силами GitHub Actions. Сайт читает этот файл при открытии
страницы.

## Как это работает

1. Ты публикуешь новый релиз на GitHub (`Releases → Draft a new release`),
   прикрепляешь JAR-файл.
2. Workflow `.github/workflows/update-releases.yml` автоматически
   запускается (при публикации релиза, по расписанию раз в 6 часов и по
   кнопке вручную), собирает актуальный список релизов через GitHub API и
   коммитит обновлённый `releases.json` обратно в репозиторий.
3. GitHub Pages пересобирает сайт после коммита, и посетители видят новую
   версию — без правки `index.html` или `script.js`.

## Формат тега релиза

Версия Minecraft достаётся из **тега релиза**, формат:

```
v<версия мода>-mc<версия Minecraft>
```

Примеры: `v1.4.2-mc1.20.1`, `v2.0.0-mc1.19.2`. Если тег не соответствует
формату, сайт всё равно покажет релиз, но версия Minecraft будет отмечена
как «unknown».

## Развёртывание

1. Загрузи содержимое этой папки в корень репозитория
   `cooolnikel-sketch/dozacraftmod` (или в ветку, с которой раздаётся Pages).
2. В настройках репозитория **Settings → Pages** включи публикацию из нужной
   ветки/папки (обычно `main` / корень, либо ветка `gh-pages`).
3. В **Settings → Actions → General → Workflow permissions** выбери
   **Read and write permissions** — без этого workflow не сможет
   закоммитить `releases.json` обратно в репозиторий.
4. Создай первый релиз с тегом вида `v1.0.0-mc1.20.1` и прикреплённым
   JAR-файлом. Workflow запустится автоматически; можно также запустить его
   вручную через **Actions → Update releases.json → Run workflow**, чтобы не
   ждать.
5. Открой опубликованный GitHub Pages адрес — релиз должен появиться в
   разделе «Все версии», а кнопка «Скачать последнюю версию» — вести на JAR.

## Файлы

- `index.html`, `style.css`, `script.js` — сам сайт.
- `config.js` — владелец/имя репозитория (`cooolnikel-sketch/dozacraftmod`);
  меняй здесь при переносе в другой репозиторий.
- `releases.json` — генерируется автоматически, в репозитории лежит пустая
  заготовка на случай, если workflow ещё не запускался.
- `.github/workflows/update-releases.yml` — сборка `releases.json` из
  GitHub Releases.
- `assets/dozacraft-gameplay.png` — скриншот геймплея для героя страницы;
  можно заменить своим.

## Ограничения

- Без собственного сервера владелец публикует новые версии только через
  GitHub Releases — отдельной админ-панели с паролем в этой версии нет
  (прошлый вариант на Cloudflare Workers/KV был для серверной админки,
  здесь это не нужно).
- `GITHUB_TOKEN`, который использует workflow, создаётся GitHub
  автоматически для каждого запуска — отдельно ничего заводить не нужно.
